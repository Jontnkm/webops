## 기능별 정리

### 1. 검사 실행기 (runner)
- **문제 위치 화면 캡처**: 깨진 이미지·링크, 접근성, 휴대폰 밀림 위치를 빨간 상자로 표시해 캡처 (`output/shots/<작업ID>/`). 첫 페이지 30장, 나머지 페이지 10장까지.
- **끝까지 스크롤 후 검사**: 늦게 뜨는(lazy) 이미지까지 확인. 최대 40번·12초까지만 내림.
- **검사 범위 3가지**
  - 메인 페이지만(기본): 어떤 주소를 넣어도 사이트 첫 화면(`/`)만 검사
  - 입력한 현재 페이지: 넣은 주소만 검사
  - 웹사이트 전체 점검: ① 링크를 빠르게 훑어 검사할 페이지를 모두 확정 → ② 탭 3개로 나눠 검사. 안전 상한 300페이지(설정 가능), 넘으면 남은 주소 수를 안내
- **게시판 글 상세 옵션**(전체 점검에만): 최신 게시물 1개만(기본) / 모든 게시물. `nttId`·`bbsSn`·`articleId`·`wr_id` 같은 게시물 번호, 숫자인 `id`·`no`·`seq`·`page`, 숫자 경로 칸을 뺀 주소가 같으면 같은 모양으로 본다. `menuNo` 같은 메뉴 값은 그대로 두어 메뉴 페이지는 따로 검사.
- **공통 영역 합치기**: 여러 페이지에 똑같이 있는 문제(바닥글의 깨진 링크 등)는 1건으로 세고 `pages[]`에 해당 페이지를 모두 기록. 페이지별 점수에는 각 페이지에 반영.
- **진행 상황 출력**: `  % 단계 완료수 전체수` 줄로 서버 진행 막대에 알림.
- **검증**: `npm run verify` 49/49 통과 (Lighthouse 제외 시 45). 테스트 페이지 `sub.html`(공통 바닥글), `board.html?id=1~7`(게시판 글) 추가.

### 2. 결과 화면
- **페이지별 점수표**(전체 점검): 페이지마다 점수와 심각도별 건수, 누르면 그 페이지의 문제 팝업.
- **품질 점수**: WebOps 자체 계산식 — 문제 종류마다 심각 20 · 높음 10 · 보통 4 · 낮음 1점 감점(같은 문제는 한 번만). 검사 점수는 페이지 평균, 열리지 않은 페이지는 0점. 화면·PDF에 계산 방법을 밝힘 (Lighthouse 점수와 다름).
- **지난 검사와 비교**: 같은 주소·같은 범위의 직전 검사와 비교해 해결됨 / 새로 생김 / 그대로 / 점수 변화. 문제 목록에 '새로' 표시.
- **선택 상자**: 유형 · 심각도 · 정렬(급한 순 / 많이 발견된 순 / 유형 순). 선택지마다 건수가 서로의 조건에 맞춰 바뀜. 왼쪽 항목 카드를 누르면 유형이 함께 바뀌고 오른쪽은 개선 방안부터 보임.
- **접근성 지침**: 접근성 문제마다 KWCAG 2.2 검사항목(번호·이름·원칙) + WCAG 2.2 기준·등급을 팝업·목록·PDF에 표시. 자동 검사 규칙을 대응시킨 것이라 인증 심사 판정과 다를 수 있음을 명시.
- **발견 위치 정보**: 캡처 아래를 '이름표 칸 + 내용 칸' 표로 — 문제 내용(강조), 주소(종류별 이름), 코드 위치, 문제가 된 코드.

### 3. 기록 · 정기 검사 · 알림
- **DB 저장**: H2 파일 DB (`WebOps\data\webops.mv.db`, git 제외). 테이블은 기획서 3장 이름 그대로 `site`, `scan_job`, `scan_page_result`, `finding` + `alert_log`. 서버를 다시 켜도 기록이 남음.
- **DB 보기**: http://127.0.0.1:8080/h2-console (JDBC URL `jdbc:h2:file:../data/webops;MODE=LEGACY`, 사용자 `sa`, 비밀번호 없음). 개발용이므로 운영에서는 끈다.
- **정기 검사** (`/sites`): 사이트 등록 → 매일/매주 정해진 시각에 자동 검사. 사이트 화면에 품질 점수·문제 수·로딩 속도 추이 그래프, 검사 기록, 알림 기록.
- **알림 메일**: 접속 불가 / 접속 복구 / 새 깨진 링크 / 검사 실패. 메일 서버(`spring.mail.host`)가 없으면 보내지 않고 알림 기록에만 남김.
- **최근 검사 카드**: 한 줄 4개 × 3줄(12개), 넘으면 페이지 번호. 사이트 첫 알파벳 동그라미. 카드 삭제(DB 기록 + 결과·캡처·PDF 파일 함께 정리, 검사 중이면 삭제 불가).

### 4. PDF 보고서
- 결과 화면 'PDF 보고서' → `/scans/{id}/report.pdf`. 인쇄용 화면 `/scans/{id}/print`을 실행기(`src/pdf.js`)가 PDF로 만든다. 한 번 만든 PDF는 `runner/output/report-<id>.pdf`를 다시 쓴다(화면을 고쳤으면 지워야 새로 만들어짐).

## 설정 (application.properties)

| 설정 | 기본값 | 뜻 |
| --- | --- | --- |
| `webops.scan.max-pages` | 300 | 웹사이트 전체 점검 안전 상한 |
| `webops.runner.site-concurrency` | 3 | 전체 점검 때 동시에 여는 탭 수 (1~5) |
| `webops.runner.per-page-seconds` | 45 | 페이지가 하나 늘 때마다 더 주는 제한 시간 |
| `webops.schedule.check-interval-ms` | 30000 | 정기 검사 시각 확인 간격 |
| `spring.mail.*` | (주석) | 알림 메일 서버 |
| `webops.alert.base-url` | http://127.0.0.1:8080 | 메일 안 '결과 보기' 링크 앞부분 |
| `spring.h2.console.enabled` | true | DB 보기 화면 (운영에서는 false) |

## 오늘 겪은 함정

- Thymeleaf: 같은 태그에서 `th:if`가 `th:with`보다 먼저 처리된다 → th:if에서 th:with 변수를 쓰면 항상 거짓.
- Thymeleaf: 인라인 스크립트에서 대괄호 두 개 연속(`[[`)은 식으로 읽힌다 → 정규식에 쓰지 말 것.
- 세션 번호가 주소에 붙으면(`;jsessionid=`) 첫 화면 데이터가 비어 보였음 → `server.servlet.session.tracking-modes=cookie`.
- H2 파일 DB는 서버가 켜져 있으면 잠긴다 → 그동안 `mvnw test`는 실패할 수 있음.
- Git Bash에서 curl로 한글 폼 값을 보내면 깨진다 → Node fetch나 브라우저로 테스트.
- `npm run verify`는 4173 포트를 쓴다 → 테스트 페이지 서버가 떠 있으면 먼저 끌 것.
- 브라우저는 화면에서 약 3000px 안쪽의 lazy 이미지는 스크롤 없이도 미리 불러온다 (스크롤 효과 테스트 시 주의).
